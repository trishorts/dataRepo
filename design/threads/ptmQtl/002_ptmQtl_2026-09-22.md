## 0 · What ptmQtl is (our D1)

**ptmQtl is generic.** It extracts PTM→trait and PTM↔PTM relationships from any search-plus-quant corpus,
and it **never defines a trait**. The consuming project does that. For aging, that means `DEF-AGE-EFFECT`:
per decade, with the centre stored. aging is the first consumer, not the only one. You are the input and
the destination.

## 1 · REQ-PTMQTL-1: `ptm_stoichiometry` grain. **Answer: per-group is unusable for a continuous trait. We need per-sample values, and we have a model that doesn't wait for them.**

Your arithmetic is right. One point per group leaves a regression with nothing to fit.

**What v1 does instead (our D2):** the unit is the **modified peptidoform, per run**, not the site:

```
log I_pf(run) ~ trait(sample) + log I_proteinGroup(run)   (+ dataset random effect)
```

The trait coefficient is the PTM change **beyond** the protein change. That separates PTM change from
protein-level change, which was our G2 confound. This is a **model term, not a stored quantity**, so it doesn't
compete with `DEF-OCC-*` (see §2). It reads only `quant_values` (peptidoform and protein-group rows, per
run), which you already hold.

**Per-sample occupancy:** we want it later as a second response type, through a pluggable input. We ask
QuantProject for it (§2), not you. In mzLib, the producer is `ModificationOccupancyCalculator`, and two open PRs
there (#1286, #1337) are the place to stack it.

**Your floor question:** `intensity_is_floor = true` is **not** a value to us. It is one of the explicit
missing states in our D3 (see §3). It reaches the model as "detected at floor", never as 0.0.

**You may leave the table exactly as it is.** Per-group occupancy is a legitimate producer output. It just
isn't our input.

## 2 · REQ-PTMQTL-2: own definition or `DEF-OCC-*`? **Answer: we consume `DEF-OCC-*` and define no site quantity.**

v1 does no roll-up from peptidoform to site in any form. The peptidoform stays the unit, and each result is
keyed to the site(s) it carries. Any site roll-up we come to need goes to QuantProject as a request. Our
**model** gets a definition id (`ptmQtl:DEF-PTM-TRAIT-HURDLE v0`), registered with QuantProject so that every stored
number carries one, as your rule requires.

## 3 · Missing values (your §7 rule 1, our D3)

We use a **two-part (hurdle) model per peptidoform**, fitted only over runs where its **protein group is
quantified**:

1. Detection: logistic `P(detected) ~ trait + log I_protein`.
2. Intensity: `log I_pf ~ trait + log I_protein` on the runs where it was detected.

Both are reported, plus a combined p-value. "Appears with age" and "rises with age" are different findings.

The four missing states you named arrive as **an explicit status column**:
- protein absent: the run is dropped for this feature
- protein present, peptidoform absent: informative, counts toward the detection part
- detected at floor
- MBR-detected

Minimum support is ≥3 detected runs and ≥3 runs with the protein present and the peptidoform absent.
Otherwise the part is `not_estimable`, which is **never NULL and never a null result**.

MBR is included, gated by the PIP-ECHO q-value (`quant_values.pip_q_value`), with `detection_type`
carried through. An MS/MS-only refit flags every MBR-dependent hit.

## 4 · REQ-PTMQTL-3: artefact vs biological. **Answer: ours, as a column, never a filter. The default source is already in mzLib.**

mzLib's `Modification.ModificationType` already carries `Common Artifact` / `Common Biological` /
`Less Common` / `Metal` / …. That is our default `mod_class`, and we ship no private table. The consumer
can override it per context. aging will want deamidation left `ambiguous`, because it's their question
L1. FDR families are **split by class pair**, so the ~63k artefact sites don't consume the multiple-testing
budget of biological×biological pairs. Nothing is dropped. (Our D5, revised by D9.)

The long-term home is the mzLib modification registry: the Unimod `Artefact` classification exists in its schema but is not
mapped to `ModificationType` today. That's an mzLib PR for us to raise, not work for you.

## 5 · REQ-PTMQTL-5: output shape. **Here is one real row of each.**

**Cross-dataset feature key (our D6): the ProForma string** of the peptidoform, with engine modification names,
plus a second column with the UNIMOD-resolved ProForma. It keeps your 135 no-UNIMOD sites, covers glycan
compositions, and is engine-neutral. `ptm_site_id` stays dataset-scoped for your own joins, and we don't
replace it.

**Result 1: `trait_effects`, one row per feature × trait × scope.**

| column | example |
|---|---|
| feature_type | `peptidoform` (later `glycopeptide`, `occupancy_site`) |
| feature_key | `PEPT[Phospho]IDEK` (ProForma, engine names) |
| feature_key_unimod | `PEPT[UNIMOD:21]IDEK` |
| protein_group | `P12345;P12346` (**all** accessions, see note) |
| trait_id | `aging:DEF-AGE-EFFECT v1.2` (consumer-defined) |
| response | `pf_beyond_protein` (or `modified_fraction` from aging, `abundance`) |
| scope | `PXD036557` or `meta` |
| beta_detect, se_detect, p_detect | 0.41, 0.12, 6.1e-4 |
| beta_int, se_int, p_int | 0.18, 0.07, 0.011 |
| p_combined, q, fdr_family | 8.2e-5, 0.004, `pf_beyond_protein·biological` |
| n_detected, n_absent_protein_present, n_protein_present | 11, 6, 17 |
| estimable_detect, estimable_int | true, true |
| mbr_dependent | false |
| mod_class, ambiguity_level | biological, 1 |
| definition_id | `ptmQtl:DEF-PTM-TRAIT-HURDLE v0` |

Note on `protein_group`: we will never take the first accession. You warned that MetaMorpheus sorts group
members alphabetically, so we carry the whole group.

**Result 2: `ptm_pair`, one row per pair × result type × stratum.** A pair is **two peptidoforms, each
carrying its protein group**, stored as two real columns per side, never a string:

| column | example |
|---|---|
| result_type | `P` physical (same peptidoform) · `C` co-varying with trait · `A` residual correlation · `B` stratified/differential |
| feature_key_a, protein_group_a | `PEPT[Phospho]IDEK`, `P12345` |
| feature_key_b, protein_group_b | `AC[Acetyl]KLMR`, `Q99999` |
| same_protein | false |
| flags | `overlapping` · `same_residue_exclusive` (e.g. O-GlcNAc vs phospho) |
| class_pair | `biological×biological` |
| trait_id, stratum | `aging:DEF-AGE-EFFECT v1.2`, NULL (only `B` has a stratum) |
| sign | `+` or `−` |
| statistic, value | `spearman_rho` 0.62 (for `P`: `obs_over_expected` 3.1) |
| n, p, q, fdr_family | 142, 1.1e-9, 3.0e-6, `A·inter_protein·biological×biological` |
| definition_id | `ptmQtl:DEF-PTM-PAIR v0` |

Pairs whose peptidoforms overlap in sequence or site are flagged and **excluded** from A/B. Otherwise the
unmodified form would come out anti-correlated with its own modified form, by construction.
