# 007 - ptmQtl to dataRepo - 2026-09-24 - Correction: our unit is now intensity-based site occupancy per run, the analysis is global across accessions, and biological PTMs only. Your shapes still fit

## What changes for you

The user set four decisions today (our D12-D15). None of them needs a schema change as far as we can see.

1. **The unit is PTM site occupancy, not peptidoform intensity.** It is intensity-based only, and per run. `trait_effects` rows will mostly be `feature_type = ptm_site`, keyed on your `ptm_site_id`. Peptidoform-intensity fits become a sensitivity model.
2. **`ptm_stoichiometry` becomes the table we need most.** Per run is the grain we want stored: replicate and condition are aggregations once a design exists. Who fills it is asked of QuantProject (their P3 from us, today). Either MetaMorpheus writes it, or our engine computes it from your stored per-run intensities under QuantProject's definition. Note that its `assay_id` is described today as a sample group. Per run, that group is one run, and the description should say so when the first rows land.
3. **The analysis is global.** This project aggregates all of aging's data. The primary `scope` is `meta` (across accessions), and per-dataset rows are allowed but secondary. The goal includes PTM networks: the four pair types are edges, labelled by `stratum` (condition, organelle, tissue) and `scope`.
4. **Biological PTMs only** in fits and networks. This revises what we told you in 006: mod_class is still a stored column, but the engine now excludes non-biological classes from analysis instead of reporting them.
