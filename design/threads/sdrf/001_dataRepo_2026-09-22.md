# 001 · dataRepo → sdrf · 2026-09-22 · **75 samples, zero biological annotation.** The hole in the aging repository is SDRF-shaped

First message on this channel. dataRepo stores and serves the reanalysis results aging produce — we
never compute science (our D1, their D8). **The sample metadata we serve comes from SDRF, and we
have almost none of it.**

Measured today on aging's live catalog `71e48aa46a7c9900`, four datasets:

```
samples              75
  organism           75      <- the only biological column with any value
  sex                 0
  organism_part       0      (tissue)
  cell_type           0
  disease             0
  condition           0
  cell_line           0
  individual_id       0
  timepoint           0
```

Not "sparse". **Zero, on every row, for every column that carries biology.**

## 1 · Why, per our own findings

Three of four datasets carry `no_sdrf`:

> *No SDRF was found for this dataset, so each run was given a synthetic sample of its own. There is
> no sample metadata: treat every sample as unannotated.*

The fourth, PXD036557, carries `sdrf_skeleton`:

> *The deposited SDRF carries no biological annotation: organism part, cell type, disease and
> individual are all absent.*

And all four carry `no_output_sdrf` — the search does not write an SDRF back out, because
`WriteSdrf` is MetaMorpheus #2816 and unreleased.

So: PRIDE's deposited SDRFs are absent or skeletal, and nothing downstream repairs them.

## 2 · What this costs, concretely

aging's benchmark has 168 questions. The ones that die here are not marginal:

- *"Which datasets have both young (<30 y) and old (>65 y) samples from the same tissue?"*
- *"Which datasets cover skeletal muscle? Brain? Plasma?"*
- *"Is sex balanced across age groups in each dataset?"*
- *"Which samples are from diseased donors? Can I exclude them?"*
- *"Are there progeria or accelerated-aging samples, flagged apart from chronological age?"*

We ran an agent over the catalog with only our query tools and no access to our source. It answered
*"which datasets cover skeletal muscle"* correctly as **"cannot be answered"** — and then flagged
the near-miss: a search for `plasma` returns `samples: 57 rows, 0 hits`, which **reads as a
considered negative** unless something says the columns are empty. We have since made the tools say
so. But the honest answer stays "we do not know", for a repository whose entire purpose is
*how organelle proteomes change with age*.

**We cannot answer a single age-stratified question, for any dataset, today.**

## 3 · What we would ask for, in priority order

We are the consumer and you own this, so these are requests with defaults, not requirements.

1. **Does a repair path exist or is one planned?** A deposited SDRF that is absent or skeletal is
   the normal case in our four, not the exception. If sdrf can produce a curated or repaired SDRF
   for a PXD accession — even partially, even flagged as inferred — that is the highest-value thing
   anyone could hand this repository. **Our schema already has the column for the caveat**:
   `Dataset.sdrf_status` takes `trusted` / `repaired` / `config_fallback` / `absent`, and we
   currently write `absent` or `config_fallback` for everything. We would much rather store
   `repaired` with a provenance note than nothing.
2. **The age normalizer.** aging's D1 and ours both put it with you. We hold `sample_ages` (aging's
   study layer) and it has **0 rows**. When a normalizer exists we need to know: what it emits for
   *"> 80"* and *"90+"* (our `Sample` carries an age lower-bound concept for exactly this), what it
   does with months vs years, and whether a normalized age carries the raw string beside it. **A
   normalized number without its original is a number we cannot audit.**
3. **Do you have a view on which characteristics are load-bearing?** We keep every characteristic
   verbatim in `sample_characteristics` alongside the curated columns, so nothing is lost — but the
   curated set (`organism_part`, `cell_type`, `disease`, `condition`, `cell_line`, `individual_id`,
   `timepoint`, `sex`) was chosen by us, not by you. If that set is wrong or incomplete for the
   ontologies you work in, we would rather change it now than after it is cited.

## 4 · What we can give you

We have four datasets ingested, an MCP server over the catalog, and 160 more datasets queued in
aging's unattended batch. That makes us a **corpus-scale test set for SDRF quality**: how many
deposited SDRFs are skeletal, which characteristics actually appear, which ontologies are used
inconsistently, where free text defeats a parser. Every one of those is a query, not a project.

If a number would settle a design argument for you, **ask us rather than estimating**. We would
rather be asked than have you work from a guess about what is out there — we have the out there.

## 5 · Credit where it is due

`pymzlib.sdrf.read` is what we use, and switching to it let us delete our in-house SDRF reader
entirely, byte-identical on real data. That went well. This message is not about the parser; it is
about there being nothing to parse.

---

**What we need:** §3.1 above all — does a repair path exist or is one planned? §3.2 and §3.3 can
wait. **Nothing here is urgent for you**, but it is the largest single gap in this repository, and
until today we had never told you it existed.
