## 0 · Two corrections before any number

We gave you four refusal classes in `004-logs` §5. **Two of them do not hold**, and you should
hear that before you build anything on the list.

### 0.1 · Compara cannot separate *"no ortholog exists"* from *"no ortholog in this release"*

Our classes (1) and (2). Both present as **an absent edge**, and nothing in the dump says whether
the source looked and declined or never had the opportunity. We asserted a distinction we had not
checked was derivable. It is not.

What the data *does* support is a decomposition by **how far the inference got**, which is
strictly more honest and answers the same question — can a cross-species row be stated, or must it
refuse itself:

| class | meaning | closest to our promise |
|---|---|---|
| `no_edge_in_shared_tree` | in a gene tree that **also contains target-species genes**, but no ortholog edge to any of them — the source had the opportunity and did not call one | our (1) |
| `tree_lacks_target_species` | in a tree containing **no** gene of the target species; the tree is the unit of inference, so there was nothing to compare against | our (2) |
| `not_in_any_tree` | in the release's gene set but in **no** Compara tree — no call was ever attempted | our (4) |
| `not_in_gene_set` | not in the release's gene set at all | our (4)'s sibling; **zero for us, non-zero for you** |

That last row is the one that matters on your side. We enumerate *from* the gene set, so it is zero
by construction here. **You supply gene ids from outside it**, so it is the class you will actually
hit — an accession resolving to an ENSG that release 116 no longer contains.

### 0.2 · Class (3) exists and is empty

Our (3) was *"the source declines to type the relationship"*. Over **85,896** between-species
orthologies among the three taxa:

```
is_high_confidence = high   47,567
is_high_confidence = low    38,329
is_high_confidence = NULL        0
```

**Every between-species ortholog is typed and qualified.** The class is real — NULL is common on
*paralog* rows — but for orthology among human/mouse/rat it is empty in release 116. We kept the
code path and the test that a NULL must not collapse to `False`, because the guarantee is "empty in
this release", not "impossible".

Note the split: **45% of orthologs are flagged low confidence.** If you want only high-confidence
edges, that is nearly half the data, and it is a filter you should apply deliberately rather than
inherit.

### Triples — the number that does not follow from the pairs

| | genes |
|---|---:|
| human protein-coding | 20,131 |
| one2one to **both** rodents | 15,539 |

Those 45 are the whole reason to measure triples separately. They look clean from every pairwise
angle and are not clean as a set. **A join built on pairwise evidence alone treats them as
interchangeable.** It is a small number, and it is the kind of small number that produces one
indefensible sentence in a paper rather than a visible error.

## 2 · A trap we nearly fell into, which you will hit if you ever read these files

Worth more to you than any single number above.

The provider's README says each genome-specific homology dump contains *"an arbitrary subset"* of
that genome's orthologies, and recommends downloading both genomes' files. We took the warning and
measured what it actually costs:

| species pair | where its orthologies live |
|---|---|
| human ↔ mouse | **mouse file: 23,764. Human file: 0.** |
| human ↔ rat | human file: 22,105. Rat file: 0. |
| mouse ↔ rat | mouse file: 40,027. Rat file: 0. |

**"Arbitrary subset" means each pair lives entirely in one file, and not the obvious one.** Every
human↔mouse orthology is in the *mouse* dump. The human dump contains none of them.

So a reasonable person downloading `homo_sapiens/Compara.116.protein_default.homologies.tsv.gz` —
the file named after the species they care about — gets **100% of human↔rat and 0% of
human↔mouse**, and nothing about the result looks wrong. It is a complete-looking file with a
plausible row count. The rat file, for our three taxa, is empty.

This is your §6.1 in a different costume: *the file's name is a claim that its contents match it.*
We only caught it because we read the README before the data, which is now a standing rule here.

The three files partition rather than overlap — **0 duplicate homologies across all three** — so
the union is exact and dedup on `homology_id` is sufficient.

## 3 · What we think this means for your schema

Offered as a read, not a requirement; you own the tables.

1. **77%, not 95%.** Roughly one in four human genes is *not* a clean triple. If a cross-species
   `age_effect_meta` row requires 1:1:1, you lose a quarter of the proteome, and the lost quarter
   is not random — it is enriched for exactly the duplicated families where rodent and human
   biology diverge.
2. **The refusal class belongs in the row, not in a filter.** 2,269 human genes have no rodent
   partner at all, and *why* differs: 720 were never in a tree, 1,272 were in a tree with no mouse
   gene, 448 were in a shared tree and got no edge. Those are three different statements about how
   much is known, and only the third is close to evidence of absence.
3. **`not_in_gene_set` is yours to hit, not ours.** Zero here, non-zero for you, and it is the one
   that looks identical to "no ortholog" from the outside.
4. **45% of orthologs are low-confidence.** Whatever you do with that, do it on purpose.
