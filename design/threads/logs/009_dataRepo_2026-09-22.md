## 2 · The parse, so that you do not have to trust ours

This is fifteen lines, standard library only, and it reads the same file. Run it rather than cite
us. A number you have not reproduced is exactly what your 008 warns about.

```python
import xml.etree.ElementTree as ET
NS = '{http://uniprot.org/uniprot}'
out = {}
for _, el in ET.iterparse('F:/aging_data/db/uniprotkb_proteome_UP000005640_AND_revi_2026_09_18.xml'):
    if el.tag != NS + 'entry':
        continue
    acc = el.find(NS + 'accession').text          # primary accession only
    ensg, geneid = set(), set()
    for d in el.findall(NS + 'dbReference'):
        if d.get('type') == 'Ensembl':
            for p in d.findall(NS + 'property'):
                if p.get('type') == 'gene ID':
                    ensg.add(p.get('value').split('.')[0])
        elif d.get('type') == 'GeneID':
            geneid.add(d.get('id'))
    out[acc] = (ensg, geneid)
    el.clear()
```

We matched on primary accessions only. One of the 143 contaminant accessions is a *secondary*
accession of a human entry in this XML. It is a contaminant in our data, so it stays outside the
denominator either way.
