## What changes for you

We took the wider boundary you gave us: **cross-dataset, not only cross-version.** It is in
datarepo **0.22.0**, commit `036eaa0`, pushed to `trishorts/dataRepo` `master`.

1. **The SQL tool's response now says it.** When a query reads `pep`, `best_pep` (the peptide-level
   minimum) or `pep_q_value`, the response carries two extra fields:
   - `run_relative_columns`: which of the three it read, each with one line on what it is;
   - `run_relative_means`: rank or threshold within one dataset; do not set values, medians or
     distributions side by side across datasets or releases; compare counts at a threshold, and
     prefer `q_value` across releases.

   We put it in the response, not only in the column documentation, because an agent can skip the
   documentation and cannot skip the response. That is our D19.
   - It sees the column through an alias (`pep AS score`), a filter, a CTE, or `SELECT *` over
     `psms`.
   - **It warns and does not refuse.** Your 2.1 names two correct uses, a within-dataset ranking and
     a count at a threshold. Nothing in the text of a query tells those apart from a cross-dataset
     comparison, so a refusal would block your correct uses along with the wrong one.
2. **Your text is stored with the rows, as `pep:DEF-PEP`, owner `pep`.** It goes into every bundle
   that has PSMs. You said no method ID exists, so the version is the pair you suggested:
   `MetaMorpheus <release>; regime <regime>`.
   - The regime is read from the search's task files using MetaMorpheus's own rule
     (`FdrAnalysisEngine.cs:410-416`): `Search` with the `top-down` protease gives `top-down`, any
     other `Search` gives `standard`, and `XLSearch` gives `crosslink`.
   - Where we are not sure of the rule (glyco, RNA, or two search tasks that disagree), the version
     says `regime not recorded` rather than guess.
   - All 204 bundles in aging's store read `standard`.
3. **The column descriptions say the same thing.** `pep` and `best_pep` are marked RUN-RELATIVE.
   `pep_q_value` says it moves with `pep`. `q_value` says it does not depend on PEP and is the more
   stable column across releases (your 2.3).

For scale, on aging's current catalog (`328b2e2d7ba0e9cf`, 34 datasets), the query from our 001,
`SELECT dataset_id, median(pep) FROM psms GROUP BY 1`, gives medians from **0.0 to 0.9999999999996**.
That is over every PSM, decoys included, so it describes nothing. It is the kind of number the
guard exists to stop.
