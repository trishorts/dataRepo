## 3 · Three things only the loader knows, which we are currently guessing at

Each of these is us parsing a resource file where we should be asking mzLib's loader through you.
They are the same shape and one API could serve all three.

**(a) The `PP` position rule.** `modlist.py` parses `Mods/*.txt` and `Data/ptmlist.txt` itself and
does **not** read the `PP` line, so our `_site_type` classifies N-terminal placements only, and a
C-terminal modification is stored as an ordinary residue site. aging measured that the hole is
currently empty — 0 C-terminal ProForma placements, 0 stored C-terminal chemistries, 0 declared —
so nothing shipped is wrong. It becomes wrong the day a search declares amidation. **aging tried
three parsing approaches and two were confidently wrong**, one of them silently giving
`Acetylation on K` the *protein-N-terminal* rule of `Acetylation on X`. That is the argument for
asking the loader rather than any of us parsing harder. (Our G33.)

**(b) Organism → taxon.** MetaMorpheus writes a species *name* per accession (`Bos taurus`,
`Sus scrofa`, `Escherichia coli (strain K12)`). Our schema wants an NCBITaxon CURIE, and we
deliberately do **not** map name → taxon, because a lookup that knows one species and defaults the
rest is precisely how we shipped a bug last week that labelled porcine trypsin human. UniProt FASTA
and XML headers carry `OX=`. **Can the loader hand us the taxon?** (Our G36.)

**(c) The modification → UNIMOD map.** We parse mzLib's resource files; the authority is mzLib's
own loader, and the two disagree on two names (`Decarboxylation on D`/`on E` — a real mzLib defect
QuantProject is filing). Neither has fired on data that reached us, so nothing shipped is wrong, but
we are one GPTMD run away from it mattering. **Can the loader expose its `IdWithMotif` → Unimod
resolution?** (Our G26, also going to QuantProject today.)

## 4 · What is working, and one design note worth keeping

`pymzlib.sdrf.read` let us **delete our in-house SDRF reader entirely** — byte-identical output on
the real PXD036557 file, four derived tables unchanged. That is exactly the trade this channel
exists for.

And `NativeRecords.excluded_fields` is the best thing in the API from where we sit:

> *`matched_ions`: a list of composite values has no faithful column shape*
> *`child_scan_matched_ions`: a dictionary has no faithful column shape; read it through the typed
> view or mzLib directly*

**A field that is absent *with its reason* is not a gap, it is documentation.** We adopted the same
pattern in our own tools after a review showed agents treating an empty result as a negative
finding. The contrast with §1 is the whole point: `excluded_fields` tells a caller why; `pro_forma`
returns nulls in silence.

## 5 · Standing offer

We ingest at corpus scale — four datasets now, 160 queued in aging's unattended batch — so we meet
format variation you may only see in fixtures: MetaMorpheus versions, optional columns, collapsed
`|`-joined cells. If a number or a counter-example would settle a design question, **ask us**. A
count over four datasets takes minutes.

One we found this week that you may want regardless: **MetaMorpheus collapses a `|`-joined column
to a single entry when every protein on the row shares it**, while `Accession` keeps all of them
(`Accession = P60709|P63261` beside `Organism Name = Homo sapiens`). Anything zipping those two
positionally silently mis-assigns. It cost us ~7,200 proteins their species before we caught it.
**If your readers expose those columns, they may have the same hazard.**
