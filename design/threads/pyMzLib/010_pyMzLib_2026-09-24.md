## How to install it (Python)

**pyMzLib is on PyPI, the standard Python package index, under the name `mzlib`.** If you have
been installing it from wheel files on the GitHub releases page, or from a local build, you do not
need to anymore.

The install name and the import name differ, the same way `pip install scikit-learn` gives you
`import sklearn`:

```
pip install --upgrade mzlib        # install, or upgrade an existing install
```
```python
import pymzlib                      # the import name is unchanged
print(pymzlib.__version__)          # should print 0.2.0
```

- **Do not `pip install pymzlib`.** That name on PyPI belongs to an unrelated package by another
  author, not us.
- **If you installed an early preview** (0.1.0.dev1 to dev5 from GitHub), it was installed under
  the old name `pymzlib`. Remove it first, or the two will collide. Run `pip show pymzlib`, and if it
  reports anything, run `pip uninstall pymzlib`, then install `mzlib` as above.
- **It works with any Python from 3.9 up**, on Windows, Linux (glibc 2.28 or newer) and macOS
  (Intel and Apple Silicon). There is nothing else to install: no .NET, and no other Python
  packages. The wheel carries its own copy of mzLib. Each wheel is about 60 MB.
- **Run the command with the same Python your project uses.** If you use a virtual environment or
  conda environment, activate it first, or run `python -m pip install --upgrade mzlib` with that
  environment's `python`.
- **To pin exactly this release:** `mzlib==0.2.0`. Put it in `requirements.txt` or
  `pyproject.toml`.
- **Docs:** https://smith-chem-wisc.github.io/pyMzLib/

**Rust and R users:** mzLibRust and mzLibR use the `mzlib-bridge-<rid>.tar.gz` assets on the
pyMzLib release page.

**Please check now:**

1. **Were you waiting for a release?** Look for anything you parked "until mzLib merges and
   releases" or "until pyMzLib ships a verb". Examples are a local parser kept as a stop-gap, a
   method that used a workaround, or a pinned older version. Those can move to the released
   functions now.
2. **Are any of your pull requests dependent on a new release?** That includes PRs in your own
   repo that pin mzLib or `mzlib`, and mzLib PRs stacked on something that has now merged. Each can
   be rebased or re-pinned onto 1.0.592 / 0.2.0.
3. **Read mzLib's breaking changes before you upgrade C# code.** There are six. Three of them
   change answers without a compile error. The one Python users will see is
   **`mbr_score` is `None`, not `0`**, where a FlashLFQ peaks table has no score (mzLib #1345).
4. **mzLib's known issue, #1359:** RNA FASTAs in the DNA alphabet load with wrong masses. RNA
   searches against those databases should stay on 1.0.591 until the next release.

If upgrading breaks something, or a function you expected is missing, reply on this thread and we
will route it (island / bridge / mainland).

## Complete release notes: pyMzLib 0.2.0

Built from mzLib 1.0.592. Adds protein databases, SDRF validation, and reading many files in one call. Upgrade with:

```
pip install --upgrade mzlib
```

**Source:** `v0.1.1..v0.2.0`
**mzLib:** 1.0.592, up from 1.0.589 (#61)

#### New: `pymzlib.proteins`, for protein databases (#63)

- **`proteins.read()`** loads UniProt XML or FASTA and returns one row per protein. Each row has the organism, NCBI taxonomy id, gene names, length and monoisotopic mass. GO terms (mzLib #1336) and Ensembl transcript links come as long tables when you ask for them.
- **`proteins.resolve_genes()`** resolves proteins to stable Ensembl gene ids against a GTF you supply (mzLib #1338). It reports an outcome per protein and records the sha256 of every input.
- **`proteins.classify_peptides()`** labels each peptide `Unique`, `SharedWithinGene`, `SharedAcrossGenes` or `NotInDatabase`, treating I and L as the same residue (mzLib #1348).

#### New: SDRF validate, lint, assess, samples and ages (#64)

- **`sdrf.validate()`** reports structural findings, each with its severity, rule, line and column.
- **`sdrf.lint()`** finds concepts that several files wrote differently.
- **`sdrf.assess()`** rates each sample `Informative`, `Partial` or `Skeleton`.
- **`sdrf.samples()`** returns one row per sample and column.
- **`sdrf.parse_ages()`** reads ages in years, with their precision. A bare `63` is refused rather than guessed at.

`validate`, `assess` and `samples` each have a `_many` form that reads a whole corpus in one call.

#### New: read many files in one call (#65)

- **Every reader has a `_many` twin** (`read_spectra_many()`, `read_records_many()`, and so on). Each returns one long table with `source_index` and `source_path` columns. Set `threads=` to read several files at once; the result is the same at any value. `on_error="skip"` reads past a bad file.
- **New readers** for MetaMorpheus's `AllQuantifiedProteinGroups.tsv` and FlashLFQ's `QuantifiedPeptides.tsv` (mzLib #1347): `read_protein_groups()`, `read_quantified_peptides()` and `read_occupancy()`.
- **`read_spectra()` now reports the run:** the instrument model, its serial number, and the acquisition start time (mzLib #1349). The start time is a timezone-aware `datetime` only when the file says it is UTC. Thermo `.raw` times come back naive, because they are the instrument computer's local time.
- **`absent_fields`** on every result lists the columns this file has no source for. Those columns are `None` in every row, not a default mzLib filled in.
- **mzIdentML** is read, including `.mzid.gz` (mzLib #1313). The format count goes from 32 to 36.

#### Changed: things you may notice

- **`mbr_score` on a FlashLFQ peaks table is `None` where it used to be `0`** (mzLib #1345). This covers peaks without a score, including MS/MS rows in older tables. Current FlashLFQ tables, which have no `MBR Score` column, now read instead of failing.
- **`pro_forma` is filled on `.psmtsv` files from MetaMorpheus 1.1.11 and earlier** (mzLib #1346). mzLib now converts `full_sequence`. Ambiguous rows are still `None`. Reading is about 20% slower on those files.

#### Docs

The reference pages for each function are now generated from the bridge's per-command specs. These are shared with mzLibRust and mzLibR, so the three bindings document the same facts. The docstring examples now run in CI (#62).

Full list: [CHANGELOG](https://github.com/smith-chem-wisc/pyMzLib/blob/v0.2.0/CHANGELOG.md).

**mzLibR and mzLibRust** get the new commands through the `mzlib-bridge-<rid>.tar.gz` assets below.

## Complete release notes: mzLib 1.0.592

### mzLib 1.0.592 — one digestion path, RNA fixed modifications, and four new readers
**Source:** `1.0.591..1.0.592` (`45386c82..c8ee03e5`, 40 PRs)
**Contributors:** @acesnik, @Alexander-Sol, @nbollis, @trishorts

This release changes public API in six places, and three of them change answers without a compile
error. **Code that implements `IDigestionParams`, `IBioPolymer` or `IHasSequenceVariants`, calls
`ProteinDigestion`, or reads `QuantifiedPeak.MBRScore` must change before upgrading.** Everything
else needs a recompile only. MetaMorpheus production code builds unchanged, but **settings written
through a generic TOML mapping of `DigestionParams` no longer load**, and MetaMorpheus and
ProteaseGuru both do that; see the first item. MetaMorpheus's test project also needs three test
doubles updated.

**Known issue (#1359):** RNA FASTAs written in the DNA alphabet (Ensembl, NCBI Assembly, NCBI RefSeq)
load with a fixed 5-methyluridine on every former T, so their masses are wrong. All-lowercase ACGT
FASTAs are skipped. Both come from #1343's MODOMICS detection and will be fixed in the next release.
RNA searches against those databases should stay on 1.0.591 until then.

#### Breaking changes

- **Digestion settings written to TOML no longer read back (#1318)** — `DigestionParams` and
  `RnaDigestionParams` gained the public, get-only `SpecificDigestionAgent`. A Nett TOML mapping
  that serialises these types by reflection now writes `SpecificDigestionAgent = "trypsin"`, and
  cannot convert it back into a `DigestionAgent` on read. So **every settings file such a consumer
  writes fails to load**, with `Failed to convert TOML object with key 'DigestionParams'`. Nothing
  fails at compile time. The property is derived from the named protease or RNase, so ignore it
  exactly as `DigestionAgent` already is:
  `.ConfigureType<DigestionParams>(t => t.IgnoreProperty(p => p.SpecificDigestionAgent))`, and the
  same for `RnaDigestionParams`.
  - **ProteaseGuru:** fixed in ProteaseGuru #108.
  - **MetaMorpheus:** needs the same two lines in `MetaMorpheusTask`'s TOML settings. Without
    them, its task-settings round trips fail, protein and RNA alike (`TestTomlFunction`,
    `TestDigestionParamsTomlReadingWriting`, `..._Rna`). Tracked in #1358.
- **Protein and RNA digestion run through one shared `DigestionAgent` (#1318)** — the
  `ProteinDigestion` class is removed; call `Protein.Digest(DigestionParams, ...)` instead.
  `IDigestionParams` now requires `SpecificDigestionAgent`, and
  `Protease.GetCleavageSpecificity(Protein, ...)` moves to
  `DigestionAgent.GetCleavageSpecificity(IBioPolymer, ...)`. RNA digestion now honours semi- and
  non-specific search modes. Anyone who implements `IDigestionParams` must add the member. That
  includes MetaMorpheus's `BadDigestionParams` (`Test/ParameterTest.cs:402`) and
  `AgentlessDigestionParams` (`Test/DigestionAgentNameTests.cs:128`). **Protein digestion results
  are unchanged.**
- **Proteins and RNA carry per-residue fixed modifications (#1342)** — `IBioPolymer` gains the
  required member `OneBasedFixedModifications`, and digestion applies it without also generating the
  unmodified form. Variants and decoys carry it too. `IHasSequenceVariants.CreateVariant` gains an
  `IDictionary<int, Modification> oneBasedFixedModifications` parameter, inserted **before**
  `sampleNameForVariants`, so both implementers and positional callers break. MetaMorpheus's
  `TestBioPolymer` (`Test/Transcriptomics/RnaDatabaseLoadingTests.cs:146`) needs both changes.
  Results for biopolymers without fixed modifications are unchanged.
- **`QuantifiedPeak.MBRScore` is now `double?` (#1345)** — current FlashLFQ and MetaMorpheus 1.1.11
  `AllQuantifiedPeaks.tsv` files threw `HeaderValidationException` and now read, including the new
  PIP Q-Value, PIP PEP, FWHM, decoy and random-RT columns. The score is **null, not 0**, when the
  column is absent or blank, and that includes MSMS peaks in older tables. Arithmetic on it stops
  compiling. A comparison such as `MBRScore > 0.5` still compiles but is now `false` for a missing
  score. Anything built against 1.0.591 must be recompiled. Tracked in #1358.
- **RNase cyclic-phosphate termini are cleavage modifications (#1332)** — `Rnase`'s
  `ThreePrimeTerminusRemainder` and `FivePrimeTerminusRemainder`, and the matching constructor
  parameters, are removed. In `rnases.tsv`, the two remainder columns are replaced by
  `CleavageModification` and `CleavageModificationType`.
  - **A custom `rnases.tsv` that still uses the old columns is not rejected.** Its termini are
    silently ignored, so migrate it.
  - RNase 4, Cusativin, MC1, PhyM and colicin_E5 give products with the same masses, but their full
    sequences now carry `[Digestion Termini:Cyclic Phosphate on X]`. That changes full-sequence
    keys in MetaMorpheus, spectral libraries and FlashLFQ.
  - `Digest` now appends the cleavage modification to the caller's own fixed or variable
    modification list.
  - `Modification.Equals`, `GetHashCode` and `CompareTo` now depend on the runtime type, so
    MetaMorpheus should re-check its `Glycan : Modification` comparisons.
  - Protease behaviour is unchanged.
- **`RnaDbLoader.SanitizeAndTransform` returns fixed modifications (#1343)** — the method gains an
  `out Dictionary<int, Modification>` parameter, and the old overload is removed. RNA FASTA and XML
  readers now recognise MODOMICS-annotated sequences and attach their modifications as fixed.
- **`Ms1FeatureFile.FromMassFeatures` gained a parameter (#1305)** — see Changed answers. Source
  compiles unchanged; binaries built against 1.0.591 must be rebuilt. Tracked in #1358.
- **`ApplyVariants`' `maxAllowedVariantsForCombinitorics` parameter is spelled correctly (#1222)** —
  it is now `maxAllowedVariantsForCombinatorics`. Only callers that pass it by name must rename it.
  `SequenceVariation.AreValid` still judges coordinates only.
- **`FlashLfqEngine` takes an optional `rnaMode` (#1319)** — see New. Its convenience constructor
  gained a trailing argument, so rebuild.

#### Changed answers

- **Consensus features are written as one charge-span row again (#1305)** —
  `Ms1FeatureFile.FromMassFeatures` writes one Min..Max row per feature, not one row per contiguous
  charge run. The split form cost 16% of confident top-down proteoforms on two Jurkat fractions
  (405 to 341). The joined form restores all 405. Pass `splitGappedChargeRuns: true` to keep the
  1.0.591 form. The feature reader is unchanged.
- **Protein N-terminal occupancy counts forms that start after a removed initiator Met (#1337)** —
  N-terminal acetylation occupancy now includes those forms in both numerator and denominator, so
  protein-group occupancy values change. Residue-1 occupancy is unchanged.
- **Modifications survive on residues an anchored insertion or deletion keeps (#1308)** — a phospho
  on the T of a UniProt `T→TAG` insertion used to vanish from the variant proteoform. It now
  survives and shifts, and MetaMorpheus attributes it to the protein rather than the variant.
  Modifications on residues the variant really changes are still dropped.
- **RNase_MC1 no longer cleaves at GpU (#1309)** — `AAGUAU` now gives `AAGUA, U` instead of
  `AAG, UA, U`. A custom `[X]|Y` motif now checks the residue *before* the cut. No shipped protease
  is affected.
- **UNIMOD ids match whole and respect termini (#1313)** — `UNIMOD:1` no longer also matches 10, 21
  or 127. This affects every caller that converts UNIMOD ids through `SequenceConversion`, not only
  mzIdentML, so re-check golden outputs with terminal UNIMOD modifications.
- **FlashLFQ envelope intensity is divided by the absolute charge (#1319)** — negative-mode
  identifications no longer give negative intensities, in RNA mode or not. Positive-mode peptide
  results are unchanged.
- **`MakeIdentifications` skips records whose spectra file was not supplied (#1344)** — it used to
  throw. Callers that relied on the exception to find missing files must check for them explicitly.
- **The spectra-file adapter's `WriteResults` honours or refuses the extension (#1204)** — `.mgf` now
  writes MGF instead of `out.mgf.mzML`. `.raw`, `.d`, `.msalign` and other read-only extensions throw
  `ArgumentException` instead of writing `out.raw.mzML`. Bare paths still get `.mzML` appended.
- **`SpectrumMatchFromTsv.ProForma` is filled for older MetaMorpheus files (#1346)** — when a psmtsv
  has no ProForma column (MetaMorpheus 1.1.11 and earlier), it is computed from Full Sequence on
  first access. Ambiguous sequences still give null, and the first access loads the modification
  databases. Code that used a null ProForma to mean "old file" must stop.
- **mzIdentML reads what real writers produce (#1306)** — spectrum IDs are now returned for MS-GF+
  and Scaffold files (null before). MGF titles are read instead of Mascot's identity threshold.
  Proteome Discoverer's userParam-only items give -1 instead of throwing. A q-value term with no
  value reads as absent, not 0.
- **The SDRF drift lint understands `comment[searched data file]` (#1335)** — pooled SDRFs carrying
  that column no longer report spurious filename drift, and
  `SdrfQuantAudit.UnmatchedButSearchedFileOnDisk` names acquired files found under their searched
  name.
- **mzML written by mzLib includes the instrument serial and start time when known (#1349)** — see
  New.

#### New

- **Four new readers, and `SupportedFileType` goes from 32 members to 36 (#1313, #1347)** — `.mzid`
  and `.mzid.gz` load as spectral matches (`MzIdentMLRecord`). Unrepresentable items are listed in
  `SkippedMatches`, not dropped. MetaMorpheus `AllQuantifiedProteinGroups.tsv` and FlashLFQ
  `(All)QuantifiedPeptides.tsv` load with per-sample counts, intensities and parsed PTM site
  occupancy. The new members are appended, so existing integer values are unchanged. A `switch`
  with a throwing default will throw on them. No new package dependency: `MzIdentML.dll` was already
  packed.
- **Peptide uniqueness with I=L and genes (#1348)** — `PeptideUniquenessClassifier.Classify` labels
  each peptide NotInDatabase, Unique, SharedWithinGene or SharedAcrossGenes. It classified 2,153,939
  human tryptic peptides in 20.2 s. MetaMorpheus and ProteaseGuru parsimony are unchanged until they
  adopt it.
- **Ensembl gene resolution (#1338)** — `EnsemblGeneResolver` maps proteins to stable Ensembl gene
  ids against a release-pinned GTF you supply. Each result records its provenance and an explicit
  outcome (Resolved, MultiGene, OffPrimaryOnly, NotInSource, ...).
- **Gene Ontology terms on proteins (#1336)** — `Protein.GoTerms` returns the deduplicated GO terms a
  UniProt XML already carries, with aspect and evidence codes. Decoys have none.
- **RNA quantification in FlashLFQ (#1319)** — setting `FlashLfqParameters.RnaMode` switches isotope
  modelling to nucleotides and a ribonucleotide averagine.
- **MODOMICS sequences (#1340, #1343)** — a "Modomics" parser for one-letter RNA sequences, tried
  after every existing parser, so current auto-detection is unchanged.
- **Instrument serial and acquisition start time (#1349)** — `SourceFile.InstrumentSerialNumber` and
  `AcquisitionStartTime` are read from mzML and Thermo RAW.
  - The timestamp is `Utc` only when the mzML states an offset.
  - RAW times are `Unspecified`, meaning local instrument-PC time.
- **SDRF:**
  - **Informativeness (#1325):** `SdrfSampleInformativeness.Assess` tells a spec-valid but empty
    skeleton from one that describes a design. On the bigbio annotated corpus it gives 300
    informative, 742 partial and 194 skeleton.
  - **Ages (#1326, #1333):** `SdrfAge.TryParse` reads `characteristics[age]` into years with a
    precision. It parses 89% of 53,655 real cells and refuses bare unitless numbers. A degenerate
    range like `40Y-40Y` is exact.
  - **Sample facts (#1334):** `SdrfSampleBlock.BySourceName` lifts each sample's characteristics
    and factors from a deposited SDRF so a search can write them back.
  - **Searched data file (#1327):** `SdrfAssay.SearchedDataFileName` writes
    `comment[searched data file]`.
  - **Bare TMT labels (#1307):** `SdrfBuilderOptions.LabelForm = Bare` writes `TMT127N`, the form
    sdrf-pipelines 0.1.6 requires.
  - **Atomic writes (#1324):** `SdrfDocument.WriteResults` writes a temp file and renames it, so a
    crash cannot leave a truncated SDRF.
  - Every new SDRF option is opt-in, and output without it is byte-identical.
- **Isobaric channels named by sample (#1300)** — setting `IsobaricQuantSampleInfo.SampleName` makes
  a channel's column `{sample}_{file}_{channel}`. Nothing changes until a caller sets it.

#### Fixes

- **Correct Unimod accessions for decarboxylation (914 → 1915) and homoserine lactone (10 → 11)
  (#1245)** — masses are unchanged. Protein XML and mzIdentML now name the right Unimod record. The
  decarboxylation fix reaches MetaMorpheus only once it stops shipping its own `Mods.txt`
  (MetaMorpheus#2749).
- **Negative PSI-MOD formal charges keep their sign (#1299)** — `1-` used to read as `+1`. No current
  UniProt modification is affected.
- **A gzipped database can be loaded by several processes at once (#1298)** — each load decompresses
  to its own uniquely named file and deletes it, even when the read fails.
- **psmtsv rows with empty accession, gene or organism cells read (#1322)** — they used to throw
  `NullReferenceException`.
- **Database paths with spaces survive MetaMorpheus prose files (#1316)** —
  `MetaMorpheusProseFile.DatabasePaths` used to cut a path at its first space.

#### Test-only and cleanup

- **Chemistry and Deconvolution mutation-testing gaps (#1233, #1235)** — test-only; no production
  changes.
- **Sequence-variant corpus: range-encoded insertions and a sliding cut site (#1321)** — test-only.
- **Remove an unused variant-application flag (#1203)** — no behaviour or API change.

#### Downstream

- **MetaMorpheus** builds its production code against this release, but it cannot reload the task
  settings it writes until `SpecificDigestionAgent` is ignored in its TOML settings (the first
  breaking item). Its test project also needs `SpecificDigestionAgent` on two `IDigestionParams`
  doubles, and `OneBasedFixedModifications` plus the new `CreateVariant` signature on
  `TestBioPolymer`. mzLib's integration job on `c8ee03e5` stopped at those three compile errors, so
  it never reached the TOML failures. The bump is MetaMorpheus #2851.
- **ProteaseGuru** needed the TOML ignore and nothing else. It is on 1.0.592 as of ProteaseGuru #108.
- **FlashLFQ** uses none of the removed or renamed symbols. It is on 1.0.592 as of FlashLFQ #185.
