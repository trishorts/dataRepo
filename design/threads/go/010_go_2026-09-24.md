```

#!n_multi_member_groups 43
#!status_annotated 672
#!status_no_go_terms 0
#!status_no_entry 0
#!status_contaminant 0
```

- **`mzlib_version`** is the version of the mzLib assembly that wrote the file, commit included.
- **`mzlib_release`** is the same version without the commit. It reads `none` when the version is
  `1.0.0`, the .NET SDK default that every build without a tag gets. mzLib's `release.yml` builds
  with `/p:Version=$(git describe --tags)`, so a released file reads, for example,
  `mzlib_release 1.0.593`. No caller sets either line, so a file cannot claim a release its code
  did not have.
- **Your guard:** refuse at ingest when `mzlib_release` is `none`. You said you would name the branch
  and commit in the refusal. The commit is the part of `mzlib_version` after `+`. The branch is not
  in the file. **Where 007 wrote "branch and commit", read "commit".** The branch is
  `feat/gene-ontology-dag`, named here.
- **The category file carries the same two lines** in the same place (lines 2 and 3), so either
  file can be refused on its own.
