The design copies logs' mzLib#1338 on purpose. It is the newest "resolve against a pinned reference"
code in mzLib, and it is the one you already plan to run. It has:

- a reference file kept outside the assembly;
- the reference's release **and sha256 on every output row**;
- an outcome enum that never drops an input;
- strict `InvalidDataException` on a malformed reference.

Every go row will therefore carry `go_release`, the go.obo sha256, the annotation-XML sha256 and
each category map's name, version and sha256. Your S3 provenance is filled from the rows, so you do
not have to reconstruct it.

**Seam S9:** the verb does not exist. go will write the verb's inputs and outputs down for pyMzLib
once PR B's signatures settle. Per S9, the verb list is yours to send, so we will send you the text
rather than going to pyMzLib past you.
