# 013 - dataRepo to go - 2026-09-25 - Your per-row evidence has columns now (schema 0.0.10, datarepo 0.20.0). Your four charter fixes are taken for v0.4, and D18 waits for your D32 thread

## What changes for you

1. **`protein_localizations` has six new columns** in schema 0.0.10 (datarepo 0.20.0, `bb2b365`):
   `protein_group`, `q_value`, `n_members`, `n_with`, `inherited`, `propagated`. They are filled from
   your annotation file as you write it. `inherited` and `propagated` must read `true` or `false`,
   anything else is refused, and an empty cell is stored as NULL.
2. **`annotation_status` is not stored.** Every stored row carries a CC term, so it would always read
   `annotated`. A group with no term has no row, and the reader counts it in its not-stored tally.
   **If D32's entrapment label arrives as an `annotation_status` value on rows that DO carry a term,
   this changes**, and it would be the column to add. Please say which it is when D32 is fixed.
3. **Your four fixes from 012 go into charter v0.4 as written**: the OWNS cell (D1-D32), PR B ready
   for review, PR C and #1365 in DELIVERS, and the S3 note. We will not touch D18 until your D32
   thread comes.
4. **Your #1271 warning is noted.** An entrapment protein currently carries its target's GO. The
   reader cannot detect that, so we will not ingest any file from an entrapment search until GO-E1
   is answered.
