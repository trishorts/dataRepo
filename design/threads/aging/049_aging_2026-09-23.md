# 049 - aging to dataRepo - 2026-09-23 - `read_psmtsv` cannot ingest a 1.75 GB `AllPSMs.psmtsv`: the bridge fails with "Insufficient memory" on a 512 GB machine. Please read it in windows

## The ask (DATAREPO-37)

**PXD032044 cannot be ingested, on 0.15.0 or 0.16.0.** It is a 44-file rat deposit that searched cleanly
overnight (680,867 target PSMs at 1% q-value, 49.9% ID rate). `AllPSMs.psmtsv` is **1.75 GB**. The largest
one that has ingested so far is PXD058611's at 347 MB. Every large deposit from here on will hit this.

```
File ".../datarepo/ingest.py", line 319, in ingest_dataset
    psm_columns = read_psmtsv(all_psms_path, log)
File ".../datarepo/readers.py", line 121, in read_psmtsv
    records = readers.read_records(str(path), timeout=None)
File ".../pymzlib/readers.py", line 868, in read_records
    data = _bridge.invoke(*args, timeout=timeout)
pymzlib._bridge.BridgeError: Insufficient memory to continue the execution of the program.
```

**Why it is not the machine.** The machine has 512 GB of RAM. `read_records` returns the whole table as a
single JSON envelope on the bridge's stdout (`_bridge.py:235-245`). "Insufficient memory to continue the
execution of the program" is .NET's `OutOfMemoryException` text, and it is what .NET raises when one
string or array would exceed its ~2 GB single-object limit. A 1.75 GB TSV serialised as column JSON is
past that limit. We have not confirmed this inside the bridge, so treat it as the likely mechanism,
not a verified one.

**What already exists to fix it.** `read_records` takes `limit` / `offset` (a window) and `out=` (write a
TSV and return only a summary). `read_psmtsv` uses neither: `src/datarepo/readers.py:121` is unchanged
in 0.16.0 (`13f7a87`). Reading in windows of, say, 200k records would keep every payload far below the
limit without changing what gets stored. Which approach to take is your decision.

**Asked:** can `read_psmtsv` (and any other reader that goes through `read_records` whole-file) read in
windows? If you think this belongs in pyMzLib (a bridge that streams, or one that refuses to build a
payload it cannot serialise, with a clear message), tell us and we will ask them. We have not posted it
there.
