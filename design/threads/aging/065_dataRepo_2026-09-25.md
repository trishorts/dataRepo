# 065 - dataRepo to aging - 2026-09-25 - DATAREPO-51 shipped in 0.19.1 (`5a09da7`): an excluded file is not a run and is a finding. It shows that your `id_rate.ms2` still counts the excluded file

## What changes for you

1. **DATAREPO-51 is fixed in datarepo 0.19.1**, commit `5a09da7`, pushed to `trishorts/dataRepo`
   `master`. A file named in the search provenance's `excluded_files` now gets:
   - no run row, no run metrics, and no SDRF assay;
   - no entry in your run-enrichment map either. An entry for it is dropped there, where before it
     would have refused the ingest;
   - one finding, `code = excluded_from_search`, severity `info`, with `finding_id =
     <PXD>:excluded_from_search:<file name>`. The message gives your reason and the deposited sha256.
2. **`INGESTER_VERSION` 0.13.0 -> 0.14.0, so every bundle id moves.** Rows change only in datasets
   whose search excluded files, which is PXD051644 today. Schema 0.0.9 and `CATALOG_VERSION` 5 are
   unchanged, so 0.19.0 and 0.19.1 bundles can share a catalog. You can re-ingest just PXD051644 if you
   prefer.
3. **DATAREPO-52 (new): your `id_rate.ms2` counts the excluded file.** Details in §1.

## 1 - What the fix showed: DATAREPO-52

We scratch-ingested PXD051644 from your disk on `5a09da7`. `runs` now reads 23 and agrees with your
23. The `ms2_spectra` check then reports a mismatch:

| source | MS2 scans |
|---|---|
| bundle: sum of `runs.ms2_spectra` over the 23 searched files | **381,822** |
| MetaMorpheus `results.txt`, `All MS2 Scans` | **381,822** |
| your search `provenance.json`, `id_rate.ms2` | **381,923** |
| `qc_report.json`, `240316_JaromeMale_M1_01.raw` (the excluded file) | 101 |

381,923 - 381,822 = 101. **`id_rate.ms2` is summed over the QC report, excluded file included**, while
the search saw 101 fewer scans. So the id-rate denominator for PXD051644 is 101 scans too large (6.40%
either way at this size, but not in general). The finding in the bundle is `count_mismatch` on
`ms2_spectra`. It is correct, so we have not silenced it.

**DATAREPO-52:** please compute `id_rate.ms2` over the searched files only, or say that it is meant to
cover the whole deposit. If it is the whole deposit, tell us, and we will reconcile against
`results.txt` instead when `excluded_files` is present. Our default until you answer is to leave the
check as it is.
