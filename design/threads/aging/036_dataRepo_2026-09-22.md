## 1 · Where the species actually is

Run against your own catalog `71e48aa46a7c9900`, four datasets, schema 0.0.7:

```
proteins, by source and flag

  source_db      contaminant   rows     organism   organism_name
  uniprot        false        45,211     45,211       42,533
  decoy          false        41,510          0       36,987
  contaminants   true            442          0          433
```

Your three numbers are all there and all explained:

- **442 contaminants with NULL `organism`** — deliberate. A contaminant panel is bovine, porcine,
  ovine and bacterial by design, so the *dataset's* taxon is not evidence about those rows. 433 of
  them carry a species in `organism_name`.
- **41,510 NULL non-contaminants** — the ones you could not account for. They are **decoys**.
  `source_db = 'decoy'`, NULL by design: a reversed sequence is no organism's protein at all.
- **"rows carrying ANY non-human organism: 0"** — true of `organism`, which holds **NCBITaxon
  CURIEs**, and there is no non-human CURIE in there because we never assign one.

**Your hypothesis is wrong in an informative way.** There is no name-to-taxon resolver that knows
only *Homo sapiens*. **There is no resolver at all**, deliberately (D1, G36): mapping `Bos taurus` →
`NCBITaxon:9913` is a reference resource we do not own, and inventing a partial one is how the
original defect happened in the first place — a lookup that knows one species and defaults the rest
is exactly the shape that labelled trypsin human. So the two facts live in two columns:

| column | holds | rule |
|---|---|---|
| `organism` | NCBITaxon CURIE | the taxon of the **database the entry came from**; NULL for contaminant-panel and decoy entries |
| `organism_name` | the producer's own species string, verbatim | whatever MetaMorpheus wrote, never parsed, never mapped |

(*Hevea brasiliensis* is rubber — glove protein. *Aequorea victoria* is GFP. The panel is telling you
about the bench as well as the sample.)

*"Human serum albumin is detected in all three datasets"* — **refutable now, and the answer is no:**

```
P02769  ALB  organism_name 'Bos taurus'    accepted at q = 0.0 in all four datasets  <- bovine
P02768  ALB  organism_name 'Homo sapiens'  accepted at q = 0.0 in three              <- human
```

One caveat worth having, because it caught our own reviewer: **`organism` is per dataset and
`protein_index` flattens it.** P02768 is a worked example:

```
P02768  PXD027318  NCBITaxon:9606  Homo sapiens  uniprot        contaminant=false
P02768  PXD032202  NCBITaxon:9606  Homo sapiens  uniprot        contaminant=false
P02768  PXD023381  NULL            Homo sapiens  contaminants   contaminant=true
P02768  PXD036557  NULL            Homo sapiens  contaminants   contaminant=true
```

Same molecule, two provenances: in two datasets it came from the search proteome and in two it
arrived through the contaminant panel. Both `organism` values are correct — the column is about the
**database the entry came from**, not the molecule — and `is_contaminant` is likewise per dataset.
`organism_name` reads `Homo sapiens` in all four, so **for a species question use `organism_name`,
and for a per-dataset contaminant question go through `proteins`, never the flattened
`protein_index`.**
