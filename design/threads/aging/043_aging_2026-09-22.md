# 043 - aging to dataRepo - 2026-09-22 - `ptm_sites` puts a shared peptide's modifications on the wrong protein positions: 2,266 wrong, 2,166 missing, none at level 1. The spans column is de-duplicated, the same collapse as `Organism`

and your code) and not only from the catalog. The reference implementation to diff against is attached as a script.

A check that needs no interpretation puts a floor under it: **1,452 `ptm_sites` rows name a residue that is not at

**By ambiguity level:** level 1 has 74,498 sites correct and 0 mismatched (1 beyond length). Every wrong site

defect has never shown under the level-1 filter, as the comment in your code predicted.

## 2 - The cause, in the file and in the code

MetaMorpheus writes `Start and End Residues In Full Sequence` **de-duplicated**, not one span per accession:

```
Accession                          Start and End Residues In Full Sequence
P60709|P63261|Q6S8J3               [216 to 238]|[916 to 938]
P60709|P63261|P68032|Q6S8J3        [239 to 254]|[241 to 256]|[939 to 954]
```

Beta- and gamma-actin share a span, so it is written once. Across all ten psmtsv files, **140,818 of 1,840,056 target
PSMs at 1% FDR have a span count different from their accession count**, which is 69% of the multi-accession
ones. **9,093 of those have MORE spans than accessions**, because a peptide repeated within one protein is listed per
occurrence. So no index pairing works in either direction.

`ptm_site_rows` (`src/datarepo/sources/identifications.py`) pairs by index, with a fallback:

```python
start = starts[index] if index < len(starts) else starts[0]
```

That is the `Organism` collapse from your 036, in a second column, and it is the same family: MetaMorpheus collapses
values within a cell, and a positional zip across two cells silently misaligns.

## 3 - What is right, and what to build against

**MetaMorpheus's own occupancy output is correct.** Of 33,539 target residue-level occupancy sites, **33,531 carry the
residue their modification names**. None mismatches; 1 is beyond length, 3 are not in the database, 4 are unchecked.
The occupancy code aligns each peptide's base sequence to each member protein's sequence and reports a segment per
protein. That comes from the Methods of the occupancy manuscript, and the numbers bear it out. So:

- **R7 must take its positions from the occupancy cells**, never re-derive them from psmtsv spans. Joined against the
  current `ptm_sites`, 95.38% of target residue-level occupancy sites join, and protein-N-terminal (pos0) sites join
  476 of 476. The unjoined 1,550 are mostly correctly placed occupancy sites that `ptm_sites` has put elsewhere, so
  that rate should rise once §2 is fixed.
- **`ptm_sites` should place sites the way the occupancy code does**: locate the base sequence in each member protein
  of the search database and emit a site per occurrence. The database is identified by the sha256 already in every
  bundle's provenance (`760984e8...8838`), and the file is at `F:/aging_data/db/`, the one your 041 inventoried. This
  gives you a second reason to want it durable (our G49).

The reference is `results/r7_probe/site_positions.py` in aging (private repo, so it is inlined below). It is about 60
lines. It reads the psmtsv and the pinned XML and diffs against the catalog. Run it after your fix: `in_ptm_sites_not_recomputed`
and `recomputed_not_in_ptm_sites` should both fall to around zero. The residual should be only what a residue-level,
target-only, human-database scope leaves out, and your fix will tell us whether our scope has missed anything.

```python
def residue_mods(full):              # (base, [(0-based index, name)]); a leading bracket is terminal
    base, mods, i = [], [], 0
    while i < len(full):
        if full[i] == "[":
            depth, j = 1, i + 1
            while depth:
                depth += {"[": 1, "]": -1}.get(full[j], 0); j += 1
            name = full[i + 1:j - 1].split(":", 1)[-1]
            if base: mods.append((len(base) - 1, name))
            i = j + (1 if j < len(full) and full[j] == "-" else 0); continue
        base.append(full[i]); i += 1
    return "".join(base), mods

# for each target PSM at q <= 0.01, for each accession a in Accession.split("|"),
# for each occurrence k of base in seqs[a]: site (a, k + index + 1, name)
```
