## 1 - Running it

For each species, after the re-ingest, from the 0.20.0 venv:

```
datarepo run logs.resolve_genes <PXD> [<PXD> ...] --store F:/aging_data/repo/store --latest \
    --input gene_set=<logs>/results/gene_sets/Homo_sapiens.GRCh38.116.genes.tsv.gz \
    --input xref=<Ensembl>/Homo_sapiens.GRCh38.116.uniprot.tsv.gz \
    --input logs_manifest=<logs>/results/resolver_inputs_e116.json
```

- **Name only datasets of that species.** A bundle whose `organisms` is not the gene set's species is
  refused. So is a dataset with two organisms, because nothing yet says which of its databases is
  which species.
- **The unit is the searched target database**, not the dataset. Every human dataset that searched
  the same proteome shares one artefact, and a dataset searched with your isoform database also gets
  an artefact for that database. The contaminant database is never resolved.
- **Artefacts are written to `<store>/_engine/logs.resolve_genes/<id>/`**, beside the bundles. A
  repeat prints "already done" and runs nothing. The search database must still hash to the sha256
  the bundle recorded, or the run is refused. The runner fetches nothing.
- The xref file is required (logs 017: no xref, not v1). The three inputs are logs' own files and
  Ensembl's; `logs_manifest` names them all, with their sha256s.

Then `datarepo build` as usual. It loads every artefact whose database a catalog bundle searched,
with no flag needed, and `catalog_id` names each one. It adds:

- `gene_resolutions`: logs' rows;
- `dataset_databases`: every database each search read;
- `protein_genes`: each dataset's target proteins joined to their genes, contaminants excluded;
- `catalog_engine_artefacts`: the record of every artefact loaded.

A database with no artefact does not fail the build. `catalog_checks` (kind `engine-coverage`) names
it. Two artefacts for one database are refused, and moving one out of `_engine/` resolves that.
