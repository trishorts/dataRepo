## 1 - The grain: per run

A run is one injection, and an enrichment is something done to what was injected: PXD058611 split
each sample into a direct aliquot and a probe-capture aliquot, and each was run on its own. So the
fact belongs on the run.

- **`runs.enrichment`**: multivalued, same vocabulary as `datasets.enrichment`, meaning the steps
  before MS for **this run**. `[none]` means whole proteome.
- **`datasets.enrichment` stays your declaration** of what the deposit is (S15 is yours). We will not
  derive it as a union of run values, because your point holds: `[none, chemical_probe]` would read
  as two steps in sequence.
- **A derived `datasets.enrichment_mixed`**, computed at ingest: true when the runs carry more than
  one distinct value. It replaces the need to read your `mixed_enrichment` flag out of a string, and
  a query can filter on it.
- **Consistency, refused on failure:** every run value other than `[none]` must appear in the
  dataset's declaration. A run that says `chemical_probe` in a dataset declared `[immunoprecipitation]`
  is a curation error, and it stops the ingest.
- **Per assay (TMT channel): not now.** In a labelled design, enrichment normally happens after
  pooling, so it is per run. If you ever meet a design where channels were enriched differently
  before pooling, tell us and we will extend it.

## 2 - Where per-run values come from

In order of precedence:

1. **The SDRF's `comment[enrichment process]`**, when an SDRF carries it, with its source per
   sdrf's option B. This is the same route as fractions, and it will land with the GeLC work, as you
   guessed.
2. **Your manifest**, where no SDRF can say it. Proposed shape (DATAREPO-44):

```yaml
  - accession: PXD058611
    enrichment: [chemical_probe]
    run_enrichment:            # deposited run base names -> steps before MS
      chemical_probe: ["178", "179", ...]
      none: ["199", "200", ...]
```

Rules, all enforced at ingest:

- **It must cover every run**, or the ingest refuses. A partial map would leave some runs NULL and
  some filled, and NULL would come to mean "probably the other one".
- **A name that is not a run in the fetch manifest is refused.** So is a run named twice.
- **No `run_enrichment`:** a dataset whose declaration is a single kind gets it on every run. A
  dataset flagged `mixed_enrichment` with no per-run source gets **NULL** on every run, never the
  dataset value, because that value is only true of some of them.

`run_enrichment` reaches written rows, so it becomes a content field in our `manifest` module and
moves PXD058611's bundle id when you add it. That is correct: the rows change.
