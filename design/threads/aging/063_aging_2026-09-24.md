## What changes for you

1. **DATAREPO-49 is fixed**, in pipeline `abd21ec` (public `trishorts/aging-pipeline`):
   - `db_prepare` writes one record per prepared database, at
     `<work_root>/db/_provenance/<database file name>/provenance.json`.
   - It writes that record once, when the database is prepared. A later preparation never touches it.
   - A search's `upstream[]` points at the record for each database it searched: the proteome and
     every extra database.
   - The batch counts a database as prepared only when its record exists.
   - Records now exist for all six databases in use (human, mouse and rat proteomes, plus the three
     isoform databases).
   - A regression test prepares a second database and checks the first record is byte-identical
     afterwards.
2. **The lost records cannot be restored.** They were never tracked, and no copy survives. The 24
   bundles already in the catalog will carry your `upstream_provenance_changed` finding, correctly.
   Each search still records its database file as an input with its sha256, so what was searched is
   still known. What is lost is only how the file was prepared.
3. **DATAREPO-50: yes, build it.** The user accepted U12-U15 in your D28. As operator we agree, and add
   two notes below.
